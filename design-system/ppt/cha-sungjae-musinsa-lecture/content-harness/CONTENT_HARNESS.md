# 차성재 강의 콘텐츠 하네스

이 문서는 PPT를 한 번 예쁘게 만드는 규칙이 아니라, 강의 메시지가 버전이 바뀌어도 흔들리지 않게 관리하는 기준이다. 장표·노트북·코드·캡처를 고칠 때 모두 같은 질문을 사용한다.

## 1. 커뮤니케이션 한 문장

> 8시간이 끝나면 처음 배우는 학습자도 **STT → LLM → Tool → LangGraph → Human Review → LangSmith** 흐름을 말로 설명하고, 무료·로컬 우선 환경에서 실패를 재현한 증거를 남길 수 있어야 한다.

강의의 중심은 특정 모델 사용법이 아니다. 실제 업무 Workflow를 **통제 가능하고, 중단 가능하고, 재실행 가능하고, 관측 가능하게 만드는 방법**이다.

## 2. 메시지 우선순위

### Level 0 · 하루 전체의 결론

- 모델은 바뀐다. 책임 경계·검증·복구·평가 증거는 제품에 남는다.
- 무료 실습은 ‘모든 도구가 공짜’라는 뜻이 아니다. 유료 서비스가 없어도 fixture·local·dry-run으로 핵심 계약을 학습할 수 있다는 뜻이다.
- Codex·Claude는 결과를 대신 책임지는 도구가 아니다. Spec → Diff → Test → Review를 빠르게 반복하는 Harness다.

### Level 1 · 여덟 블록의 역할

1. 문제정의: 오늘 만들 제품과 완료 증거를 정한다.
2. Tool Calling: 모델의 제안과 실제 실행 권한을 분리한다.
3. 한국어 PBL 데이터: 자연스러운 요약보다 사람·숫자·날짜·근거를 보존한다.
4. 환경·Git: 설치 성공이 아니라 다른 사람이 다시 실행할 수 있게 만든다.
5. Safe Loop: LLM을 붙이기 전에 validation·timeout·stop을 결정론적으로 통과한다.
6. 무료·Local LLM: provider가 바뀌어도 contract가 남는 adapter를 만든다.
7. LangGraph·HITL: 중단·승인·수정·거절·재개를 State와 event로 남긴다.
8. STT·LangSmith: trace를 쌓는 데서 끝내지 않고 READY/HOLD 배포 결정으로 닫는다.

### Level 2 · 블록 안의 진행 순서

각 블록은 아래 순서를 따르되, 같은 설명을 다른 형식으로 반복하지 않는다.

1. **질문**: 앞 블록에서 새로 생긴 문제를 한 문장으로 던진다.
2. **개념**: 이 블록이 소유한 용어와 판단 기준만 설명한다.
3. **근거 화면**: 공식 문서·실제 실행 화면에서 확인할 지점을 지정한다.
4. **코드**: 개념을 지키는 경계 한 줄을 찾는다.
5. **실험**: 강사를 따라 정상·실패를 재현한다.
6. **Gate**: 앞 내용을 다시 말하지 않고, 처음 보는 상황에 적용해 판단한다.

## 3. 반복 정책

### 허용

- 강의명·시간·페이지 번호 같은 footer chrome
- ‘한 줄로 말하면’, ‘왜 중요한가’처럼 학습자가 위치를 찾는 고정 UI 라벨
- 코드·실습 컴포넌트의 짧은 조작 라벨
- 첫 장의 과정 약속을 마지막 30분에 한 번 회수하는 것
- 점심 14시 안내는 오프닝 운영 장표 한 장에서만 상세 설명하고, 실제 점심 직전에는 시간만 표시하는 것

### 금지

- 블록 시작 장표와 다음 장표가 같은 결론을 말하는 것
- ‘이 블록이 끝나면…’, ‘화면은 네 가지만…’ 같은 범용 제목을 모든 블록에서 복제하는 것
- 중간 checkpoint가 방금 설명한 문장을 그대로 질문으로 바꾸는 것
- STT·Human Approval·LangSmith의 구현 설명을 소유 블록보다 앞에서 완결해 버리는 것
- 결론·요약·정리 장표를 블록마다 두는 것

### 중간 Gate 작성법

- 재진술 질문: “Idempotency가 왜 필요한가?” → 사용하지 않는다.
- 적용 질문: “승인 뒤 같은 request_id가 다시 들어왔다. 발행할까, cached result를 돌려줄까?” → 사용한다.
- 정답은 speaker notes에 둔다. 화면에는 상황·선택·판단 근거만 둔다.

## 4. 메시지 소유권과 예고

- 오프닝은 전체 구조를 **예고**할 수 있지만 구현 원리를 설명하지 않는다.
- Tool Calling은 Human Approval을 ‘쓰기 권한 경계’로만 예고한다.
- 한국어 데이터 블록은 STT를 ‘입력 계약’으로만 다룬다.
- 환경 블록에서 Harness Engineering을 실제 폴더·Git·테스트 루프로 구체화한다.
- Safe Loop가 timeout·retry·stop의 1차 소유자다.
- LangGraph 블록이 interrupt·resume·HITL·idempotent publish의 1차 소유자다.
- 마지막 블록이 STT 품질·LangSmith trace·dataset·evaluation·release gate의 1차 소유자다.

정확한 범위와 산출물은 `DAY1_MESSAGE_MAP.json`을 단일 기준으로 사용한다.

## 5. 장표 역할 태그

장표를 추가할 때 아래 역할 중 하나를 선택한다. 역할을 설명할 수 없으면 추가하지 않는다.

- `PROMISE`: 학습 결과·운영 계약
- `QUESTION`: 다음 블록을 여는 긴장
- `TERM`: 초심자 용어 정의
- `CLAIM`: 한 장 한 주장
- `EVIDENCE`: 공식 문서·실제 화면
- `CODE_BOUNDARY`: 계약을 지키는 코드
- `FOLLOW_ALONG`: 강사 따라하기
- `FAILURE_CASE`: 의도적 실패와 복구
- `APPLICATION_GATE`: 새 상황에 적용
- `FINAL_SYNTHESIS`: 하루 마지막 회수

같은 메시지 ID에 `CLAIM`과 `FINAL_SYNTHESIS`를 제외한 두 개 이상의 설명 장표를 연결하지 않는다. 화면·코드·실습은 같은 주장을 되풀이하는 것이 아니라 서로 다른 증거여야 한다.

## 강의 작성을 위한 Harness Engineering 기준

아래 항목은 학습자에게 가르칠 본문이 아니라, 강의 자료를 만드는 제작자가 지킬 내부 표준이다. `개발자 발표는 화면을 크게, 문장은 짧게`와 같은 제작 지침을 별도 강의 장표로 만들지 않는다.

- **한 장 한 메시지**: 제목만 읽어도 그 장표가 전달할 결론이 보이게 한다.
- **실제 화면 우선**: 서비스를 설명할 때는 메뉴 위치·실행 명령·성공 신호가 보이는 실제 캡처를 사용한다.
- **문장은 짧게**: 배경 설명은 speaker notes에 두고 화면에는 주장·근거·행동만 남긴다.
- **출처는 notes에**: 외부 이미지와 비상식적 주장은 `[Sources]` 블록으로 추적한다.
- **제작 규칙은 화면 밖에**: 장표 작성법·분량 조절법·디자인 참고 문장은 콘텐츠가 아니라 이 문서에서 관리한다.
- **반복 구조는 표로 통합**: 같은 레이아웃이 3장 이상 이어지면 비교표·의사결정표·한 장짜리 용어표로 합칠 수 있는지 먼저 본다.
- **같은 위계는 같은 색상**: 표의 열들이 같은 역할이라면 한 열만 accent 색으로 강조하지 않는다. 정말 중요한 경고·결정·상태에만 파란색을 사용한다.
- **장표 수보다 학습 흐름**: 목표 장수를 채우기 위해 같은 메시지를 분할하지 않는다. 강의 시간은 실습·오류 복구·반례·Q&A로 확장한다.
- **도구는 맥락과 함께**: 도구명만 나열하지 않고 도메인·역할·선정 이유·유사 대안과의 차이를 함께 설명한다.
- **선택 도구와 필수 도구를 분리**: VS Code·Git·fixture처럼 모두가 따라야 할 경로와 Codex·Claude·Local LLM처럼 환경에 따라 선택할 경로를 구분한다.
- **화면은 크게**: 실제 캡처는 조작 위치와 성공 신호를 읽을 수 있는 크기로 배치하고, 설명 텍스트가 화면을 밀어내지 않게 한다.

### 화면에 보여줄 것과 내부에 남길 것

| 구분 | PPT 화면에 보여줄 내용 | Harness MD·speaker notes에 남길 내용 |
|---|---|---|
| 학습 메시지 | 개념·판단 기준·업무 맥락·왜 중요한가 | 메시지 소유권·장표 역할 태그·작성 의도 |
| 실습 | 입력·실행 단계·완료 신호·실패 시 복구 행동 | talk track·소요 시간 추정·진행 속도 조절법 |
| 도구 | 도메인·역할·선정 이유·유사 대안과의 차이 | 캡처 제작 지시·레이아웃 규칙·이미지 후보 |
| 검증 | test 결과·schema·승인 조건·READY/HOLD 기준 | 중복률·밀도·장표 수·검수 메모 |
| 운영 안내 | 실제 시간표·점심·쉬는 시간·학습자 행동 | 제작자용 일정 계산·강의 운영 가설 |

- 화면의 모든 문장은 학습자가 **이해하거나, 판단하거나, 실행하거나, 완료를 검증하는 데** 직접 도움을 줘야 한다.
- `KEY POINTS`, `CORE IDEA`, `FOLLOW ALONG`, `SCREEN ROUTE` 같은 장표 역할 태그는 제작·검수용 메타데이터다. 학습자 화면에는 한국어 행동 라벨로 바꾸거나, 없어도 의미가 통하면 표시하지 않는다.
- `개발자 발표는 화면을 크게, 문장은 짧게`, 장표 밀도, 장수 목표, 디자인 변주 같은 지시는 PPT 본문에 넣지 않는다.
- 강사의 말하기 메모·심화 반례·시간 여유분은 speaker notes나 별도 운영 문서에 둔다. 학습자에게 행동을 요구할 때만 화면에 올린다.
- 위 기준을 통과하지 못한 문장은 삭제하거나 notes·Harness MD로 이동한다. 장수를 유지하기 위한 대체 장표는 만들지 않는다.

### 온라인 개인 실습 기본값

- 이 과정의 기본 운영은 **온라인·개인 실습·강사 따라하기**다.
- 짝 활동, 조별 토론, 돌아가며 발표, 화면 공유를 기본 활동으로 넣지 않는다.
- 재직 여부·회사 업무·구직 상황·개인 프로젝트 주제를 채팅창이나 전체 화면에 공개하도록 요구하지 않는다.
- 학습 결과는 기본적으로 각자의 notebook·로컬 파일·Git 저장소에 남긴다. 제출이나 공유가 꼭 필요할 때만 별도로 안내한다.
- 질문은 `첫 오류 문장 + 직전 행동 + 실행 환경 + 기대 결과`를 채팅창에 남기는 방식으로 받는다.
- Gate는 개인이 화면을 보며 판단하고, 강사가 대표 사례를 해설하는 방식으로 운영한다. 수강생 발표는 요구하지 않는다.
- 실습 문구는 `피어 리뷰`, `lane`, `발표 목표` 같은 운영 용어보다 `지금 할 일`, `완료 화면`, `막혔을 때 행동`처럼 바로 이해되는 표현을 우선한다.

### 제작 전 확인 질문

1. 이 문장은 학습자가 알아야 할 내용인가, 제작자가 지켜야 할 규칙인가?
2. 앞 장표와 같은 결론을 다른 말로 반복하고 있지 않은가?
3. 네 개의 유사 항목을 네 장으로 나누기보다 한 표에서 비교하는 편이 낫지 않은가?
4. 왜 이 도구를 쓰는지, 비슷한 도구와 어떤 차이가 있는지 설명했는가?
5. 실제 화면·코드·test 중 하나가 이 주장을 증명하는가?

## 6. Harness Engineering 검수 루프

1. `DAY1_MESSAGE_MAP.json`에서 이번 변경의 소유 블록과 산출물을 확인한다.

6. 경고는 삭제·재작성·허용 목록 등록 중 하나로 처리하고 이유를 기록한다.
7. `DAY1_AUDIT_LOG.md`에 변경 전/후 수치와 대표 수정 장표를 남긴다.
8. PPT·PDF·ipynb가 같은 메시지 ID와 용어를 쓰는지 release 전에 다시 확인한다.

## 7. 사람 검수 체크리스트

- 제목만 1→끝 순서로 읽었을 때 논리가 앞으로 전진하는가?
- 각 블록이 앞 블록의 미해결 문제를 받아 시작하는가?

- 중간 Gate는 암기 확인이 아니라 새 사례의 판단을 요구하는가?
- 마지막 30분만 하루 전체를 회수하고, 그 전에는 불필요한 요약이 없는가?
- 재직자는 승인·보안·운영 증거를, 구직자는 README·test·Git history를 남길 수 있는가?
- 학생이 강사를 그대로 따라가다 막혀도 fixture·checkpoint·dry-run으로 복구할 수 있는가?
- speaker notes의 출처와 화면의 주장이 일치하는가?

## 8. 변경 기록 원칙

- PPT 파일을 덮어쓰지 않는다. 의미 있는 개정마다 새 suffix를 붙인다.
- 메시지 변경은 먼저 `DAY1_MESSAGE_MAP.json`에 반영한 뒤 장표를 고친다.
- 반복을 의도적으로 허용하면 허용 목록에 문구·범위·이유를 함께 남긴다.
- 장표 수를 유지해야 할 때 중복 장표를 삭제만 하지 않는다. 반례·새 사례·판단 Gate·실제 화면 증거로 전환한다.
- 모델이 만든 문구는 강사가 실제로 말할 수 있는 문장인지 소리 내어 읽고 확정한다.
