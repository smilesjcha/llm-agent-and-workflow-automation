# 2일차 수강생 실습 가이드 · 회의 기록 Agent

이 문서는 수업 화면을 다시 보지 못하더라도 2일차 결과를 혼자 재실행하기 위한 안내서다. 각 차시는 `준비 파일 → 개념 → 강사 Demo → 소프트웨어 실습 → Codex Task → 성공·오류 확인 → 결과 파일` 순서로 진행한다.

웹사이트를 둘러보거나 아이디어만 적는 활동은 소프트웨어 실습으로 부르지 않는다. 이 문서에서 **소프트웨어 실습**은 파일을 열고, 코드를 실행하거나 수정하고, Test 또는 결과 파일을 확인하는 과정만 뜻한다.

## 오늘의 최종 결과

```text
Google Meet TXT ─┐
ClovaNote TXT  ──┼─→ TranscriptEnvelope ─→ Domain Context ─→ MeetingRecord
회의 녹음      ──┘       필요한 경우만 STT             │
                                                        ▼
                                              LangGraph Human Review
                                                        │
                                                        ▼
                                            Markdown · Email Draft
                                            외부 저장·발송 없음
```

## 실행 Lane

외부 API와 유료 계정이 없어도 모든 차시를 완주할 수 있다.

| Lane | 용도 | 준비 | 수업 원칙 |
|---|---|---|---|
| 구현 경로 | 모든 수강생의 기본 경로 | Python·Notebook·검토된 fixture | 결정적 Sample로 1~8차시 완주 |
| 모의 경로 | 외부 연결 계약 확인 | MCP read plan·integration plan | 실제 조회·저장 없이 `executed=false`, `PLAN_ONLY` 확인 |
| 선택 Live 경로 | 로컬·외부 Provider 비교 | faster-whisper·Ollama·OpenAI | 의존성·로그인·비용을 확인하고 직접 opt-in한 경우만 실행 |
| Coding Agent | 코드 제작·검토 | Codex 또는 Claude Code Login | API Key 없이 구독 Login 사용 가능 |

`Fixture`는 가짜 성공 화면이 아니다. 같은 입력이면 같은 결과가 나오는 검증용 Sample이며, Code·Schema·State·오류 처리의 학습 계약은 Local·Live Lane과 동일하다.

## 2차시 · Input Route · STT

### 핵심 개념

이미 전사된 Meet·ClovaNote TXT는 다시 STT하지 않는다. Notebook의 기본 Run All은 강사가 음성과 대조한 fixture 전사를 사용한다. 실제 녹음의 `faster-whisper` 전사는 의존성과 `FASTER_WHISPER_LIVE_OPT_IN=1`을 준비한 경우만 실행하며, 세 입력은 같은 `TranscriptEnvelope`로 합류한다.

| 입력 | 처리 | 보존할 정보 | 오류 처리 |
|---|---|---|---|
| Google Meet TXT | TXT Parser | 화자·시간·출처 | 빈 TXT 차단 |
| ClovaNote TXT | TXT Adapter | 참석자 번호·구간 | 화자 Mapping 확인 |
| Audio 기본 | 검토된 fixture 전사 | Timestamp Segment·검토 상태 | 해당 음성·전사 쌍만 사용 |
| Audio 선택 Live | `faster-whisper` | Timestamp Segment·Model | 실패를 fixture 성공으로 표시하지 않음 |

## 4차시 · MeetingRecord Schema

### 핵심 개념

자유로운 요약 문장을 그대로 다음 기능에 넘기지 않는다. 목적·요약·관점·할 일·인사이트를 `MeetingRecord` Field로 만들고, 사실 Field는 원문 Segment ID와 연결한다.

| Field | 작성 기준 | 모를 때 |
|---|---|---|
| Summary·Decision | 원문 근거 필수 | `CONFIRM_REQUIRED` |

```bash
ls dist/MeetingIntelligence-Windows.exe dist/MeetingIntelligence-macOS.pkg dist/SHA256SUMS
```

교육용 Package는 unsigned build다. 외부 배포 전 Windows code signing과 Apple Developer ID signing·notarization이 필요하다.
