# 4·5주차 운영안과 미니 프로젝트

3주차에는 코드 리뷰의 입력·판단·수정·검증을 PC에서 완성한다. 4주차에는 이를 GitHub PR에 연결하고, 5주차에는 회의록·리뷰·문서를 통합한 뒤 각자 서비스를 개선한다.

## 원안과 실제 수업의 연결

첨부 원안은 6개 주제를 40시간으로 배분한 문서다. 1~5주차가 각각 원안의 한 모듈에 대응하는 것은 아니다. 실제 1·2주차에서 STT, LangGraph, 회의기록, Coding Agent를 먼저 적용했으므로 이후에는 같은 개념 설명을 반복하기보다 다른 서비스에 적용한다.

| 주차 | 중심 서비스 | 원안과 연결한 교육 편성 | 앞선 과정의 활용 |
|---|---|---|---|
| 1주차 | Agent 기본기 | 모듈1 6H + 모듈2 2H | Tool Calling·실행 권한·Python·Prompt·STT 입문 |
| 2주차 | 한국어 회의기록 | 모듈2 4H + 모듈5 4H | 입력 변환·맥락·회의록·코딩 Agent·검토·Localhost |
| 3주차 | 코드 리뷰 Agent | 모듈3 8H | 회의 원문 근거를 코드 변경 줄과 Test 근거로 전환 |
| 4주차 | GitHub 자동 리뷰 | 모듈4 6H + 모듈5 2H | 로컬 검토 결과를 PR·댓글·CI·문서로 연결 |
| 5주차 | 통합 서비스·개인 프로젝트 | 모듈5 2H + 모듈6 6H | 예외 처리·실행 기록·결과 개선 |

이 시간 배분은 원안의 주제 누락을 막는 **교육 설계상의 대응표**다. 이미 진행한 1·2주차의 실제 발화 시간을 사후 측정한 수치는 아니다. 원안의 6+6+8+6+8+6=40H를 유지하면서 내용 순서를 재배치했다.

## 공통 시간 운영

한 차시 핵심 활동 50분 × 8 = 400분. 쉬는 시간 30+20+30=80분을 포함해 교육 편성 8시간이며, 점심 60분을 더해 09:00~18:00로 운영한다. 쉬는 시간은 각 연강 구간의 끝에 둔다.

| 시간 | 운영 |
|---|---|
| 09:00-11:30 | 1~3차시 (11:30-12:00 쉬는 시간) |
| 12:00-13:00 | 점심시간 |
| 13:00-14:40 | 4~5차시 (14:40-15:00 쉬는 시간) |
| 15:00-17:30 | 6~8차시 (17:30-18:00 쉬는 시간·Q&A) |

수업 결과는 학생 본인의 작은 PR과 자동 검사·리뷰 근거다. Agent가 제안한 내용과 사람이 실제 게시한 내용을 구분한다. PR Merge는 자동으로 실행하지 않는다.

## 미니 프로젝트 · 3시간 편성

5주차 15:00~18:00는 **제작·검증·정리 150분 + 쉬는 시간·Q&A 30분**이다. 180분 전체를 순수 코딩 시간이라고 표현하지 않는다. 강사 화면을 따라 개인별로 진행하며 발표를 필수로 요구하지 않는다.

| 후보 | 최소 기능 | 입력 예시 | 검증 예시 |
|---|---|---|---|
| 회의 후속 작업 도우미 | 담당자별 할 일과 기한 표시 | 합성 회의 TXT | 없는 담당자·기한은 추측하지 않음 |
| 코드 리뷰 Agent 확장 | 본인 업무 규칙 한 가지 검사 | 공개 예제 Diff | 정상 코드 오탐·결함 누락 확인 |
| PR 변경 요약·릴리스 노트 | 변경과 사용자 영향을 연결 | 교육용 PR | 실제 변경 없는 기능을 쓰지 않음 |
| 개인 문서 검토 서비스 | 문서 규칙 한 가지 확인 | 합성 안내문 | 누락 필드·잘못된 형식 검사 |

범위는 입력 1종, 사용자 기능 1개, 실패 조건 1개, 결과 화면 1개다. 4주차 종료 전 합성 입력 하나와 만들 기능 한 줄을 준비하면 충분하다. 새로운 플랫폼 전체, 복수 계정 연동, 실제 결제 등은 3시간 범위에서 제외한다.

## 개선 전후 1page

| 항목 | 작성 내용 |
|---|---|
| 사용자 문제 | 누구의 어떤 일이 불편했는지 |
| 입력과 첫 결과 | 직접 넣은 입력과 처음 나온 결과 |
| 발견한 문제 | Codex 리뷰 또는 Test에서 확인한 오류 |
| 코드 변경 | 바꾼 함수·조건·처리 한 가지 |
| 같은 입력의 결과 | 변경 전후를 나란히 비교 |
| 검증·실행 | 정상/실패 Test와 재실행 명령 |

희망자는 이 문서나 짧은 화면 녹화를 공유한다. 강사는 공개에 동의한 예시를 골라 “좋아진 점·남은 문제·다음 작은 개선”을 설명한다. 학생의 실제 회사 데이터, 계정 정보, 고객 파일을 공개하지 않는다.
