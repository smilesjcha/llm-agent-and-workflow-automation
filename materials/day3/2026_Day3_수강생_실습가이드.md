## 설치·로그인

### Python·VS Code·Notebook

Python 3.12를 권장한다. VS Code에 Python·Jupyter 확장을 설치하고 저장소 폴더를 연다.

```bash
git clone --branch codex/day3-review-intelligence https://github.com/smilesjcha/llm-agent-and-workflow-automation.git
cd llm-agent-and-workflow-automation
python -m venv .venv
```

이번 개편본은 `codex/day3-review-intelligence` branch에서 받는다. main에 남은 이전 버전과 구분한다. clone이 어려우면 제공된 `day3-student-code-bundle.zip`을 풀어 폴더를 연다. 이미 수정 중인 저장소가 있으면 기존 작업을 보존하고 다른 새 폴더에 위 branch를 clone한다. ZIP은 내려받기 방식이며, **2차시의 실제 Git 명령 실행에는 Git 설치가 필요하다.** 터미널에서 `git --version`을 확인하고 명령을 찾지 못하면 Git을 설치한 뒤 터미널·Kernel을 다시 시작한다.

macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

실행 정책으로 활성화가 막히면 `.venv\Scripts\python.exe -m pip install -r requirements-day3.txt`처럼 가상환경 Python을 직접 사용한다. macOS에서 `python` 명령이 없으면 초기 환경 생성에 `python3`를 사용한다.

```bash
python -m pip install -r requirements-day3.txt
python -m ipykernel install --user --name day3-review --display-name "Day3 Review"
```

Notebook 우측 Kernel에서 `Day3 Review`를 선택한다. Notebook 첫 셀에도 누락 library 설치 코드가 포함되어 있다. 어떤 Python에 설치했는지 `sys.executable` 출력으로 확인한다.

코드 ZIP의 준비 상태는 `python scripts/run_day3_preflight.py --code-only`로 확인한다. `--code-only`는 PPT·PDF와 Git 설치를 검사하지 않는다. Notebook 2차시까지 진행하려면 위의 `git --version`도 확인한다. 강사용 전체 저장소는 `python scripts/run_day3_preflight.py`로 강의 파일까지 검사한다.

### Codex CLI

```bash
npm install -g @openai/codex
codex --version
codex login
codex login status
```

`npm`이 없으면 Node.js를 먼저 준비한다. macOS와 Windows의 공식 설치·인증 안내는 [Codex CLI](https://developers.openai.com/codex/cli/), [인증](https://developers.openai.com/codex/auth/), [Windows](https://developers.openai.com/codex/windows/)를 참고한다.

Local Codex CLI는 PC에서 CLI가 실행된다는 뜻이며, 모델 추론은 네트워크를 사용하는 서비스다. 수업용 Adapter는 개인 설정을 제외한 CLI 기본 모델을 사용한다. 필요하면 `CodexCLIReviewProvider(model=...)`로 계정에 허용된 모델을 명시한다. 실습에 별도 API key를 입력할 필요는 없다.

Notebook에서 **`RUN_CODEX_LIVE=True`**로 바꿔 실제 CLI 리뷰를 실행한다. 기본값 `False`는 제공된 예제 리뷰를 사용한 재현 경로다. 화면에 두 경로가 구분된다. live 실패는 예제로 자동 바뀌지 않는다.

## 단계별 실습

### 1차시 · 오류 재현

1. 실습 폴더 생성 셀 실행 후 파일 경로 확인
2. `learner_payable()`에 초안 계산식 작성
3. 정상 주문 30,000원·쿠폰 5,000원 실행
4. 초과 쿠폰 10,000원·15,000원 실행
5. 실제 `checkout_checks.py` 실행 결과의 실패 확인

기대 결과: 초안 9개 Test 중 7개 실패. 상품 10,000원·쿠폰 15,000원의 잘못된 최종 결제금액은 -2,000원이다. 올바른 결과는 상품 금액 0원과 배송비 3,000원을 합한 3,000원이다. 이 단계에서 실패는 설치 오류가 아니라 결함 재현이다.

### 2차시 · 줄 번호 계산

1. `DIFF`에서 `+++`, `@@`, `+`, `-`, 공백의 역할 확인
2. `learner_added_line_map()` 직접 작성
3. 두 Hunk의 추가 줄 3·11 확인
4. 직접 구현과 정본 Parser 비교
5. 실제 `git diff --no-index` 출력 확인

삭제 줄은 새 줄 번호를 증가시키지 않는다. `+++`는 코드가 아닌 파일 헤더다. `--no-index`의 종료코드 1은 두 파일이 다르다는 뜻이다.

### 3차시 · 맥락과 요청

1. `learner_public_context()`로 규칙·변경 줄·Test만 선택
2. 관계없는 합성 메모가 제외되는지 Test
3. `learner_review_prompt()`로 baseline/refined 요청 작성
4. LangChain `ChatPromptTemplate`에 변수 연결
5. `prompt_baseline.md`, `prompt_refined.md` 비교

전문 용어를 길게 넣기보다 모델이 모르는 업무 규칙을 정확히 전달한다. 제공한 코드 주석은 분석 자료이며 실행 지시로 취급하지 않는다.

### 4차시 · 실제 CLI 리뷰

1. `codex --version`, `codex login status` 확인
2. Python subprocess의 인자 배열·표준입력·Timeout 확인
3. `RUN_CODEX_LIVE=True`로 실행
4. 사용 Provider가 `codex_cli`인지 확인
5. Markdown에서 파일·줄·재현 조건·영향·수정안 확인

Notebook Adapter는 도구를 끈 상태에서 제공된 Context를 분석한다. 반면 터미널에서 `codex`와 대화하면 허용된 프로젝트 파일을 읽고, 요청에 따라 수정·Test 실행까지 수행할 수 있다. 두 방식의 역할과 권한을 구분한다.

### 5차시 · 실제 파일 수정

1. 없는 줄 999를 넣고 `learner_grounded_candidates()`로 제외
2. VS Code에서 `starter/checkout.py` 직접 수정
3. 정수·음수 검사, 쿠폰 상한, 할인 후 배송비 구현
4. 같은 `checkout_checks.py` 재실행
5. 배송 기준 49,999원·50,000원과 음수 입력 추가 검증

수정 후 9개 Test가 통과해야 한다. 10,000원·15,000원은 3,000원, 50,000원·10,000원은 43,000원이다. Test 기대값을 바꿔 통과시키지 않는다. Notebook의 완성 예시를 적용하지 않으려면 `APPLY_LEARNER_FIX=False`로 설정한다.

CLI 요청·Prompt 비교는 코드를 수정하기 전 4차시에서 진행한다. 5차시 수정 후 앞의 리뷰 셀만 역순 실행하면 현재 파일에서 결함이 사라져 예제 결과가 달라질 수 있다. 처음부터 복습하려면 Run All로 새 실습 폴더를 만들고 위에서 아래로 실행한다. 기존 수정 파일은 보존된다.

### 6차시 · 사람 검토

1. `learner_review_decision()` 구현
2. Graph 시작 셀에서 `REVIEW_REQUIRED`와 `__interrupt__` 확인
3. 다음 셀에서 제목 편집·`REVIEW_DECISION` 선택
4. `Command(resume=...)` 재개
5. 별도 thread의 `reject`에서 결과가 제외되는지 확인

기본 예시는 `edit`다. 수정된 제목이 마지막 `review_report.md`에도 반영되어야 한다. `reject`는 게시 준비가 `HOLD`로 남는다.

### 7차시 · 오탐·미탐 비교

1. `learner_review_metrics()` 작성
2. 정답 1개·오탐 1개·미탐 1개의 Precision/Recall 계산
3. 오탐을 추가해 Precision 변화 확인
4. 결함을 빼고 Recall 변화 확인
5. 실제 CLI 결과는 재현 조건을 사람이 정답 기준과 연결한 뒤 별도 평가

고정 예제의 F1 0.5→1.0은 계산 학습용이다. 실제 Agent의 성능 향상을 측정한 수치로 발표하지 않는다.

### 8차시 · 같은 코드의 화면 실행

Notebook이 출력하는 명령에는 이번 실습 폴더가 포함된다.

```bash
python -m labs.day3.review_copilot.web --exercise-dir 이번실습폴더 --port 8765
```

`http://127.0.0.1:8765/`를 열고 주문 입력·계산·Test·리뷰·문서 기능을 실행한다. Notebook에서 `RUN_LOCALHOST_SMOKE=True`로 바꾸면 같은 서버에 HTTP 요청을 보낸다. 수정한 코드와 화면의 결과가 같아야 한다.

## 오류별 복구

| 상황 | 첫 확인 | 조치 |
|---|---|---|
| 패키지 없음 | Kernel 경로 | 현재 Kernel에 pip 설치·재시작 |
| Codex 명령 없음 | 설치·PATH | 설치 후 터미널·Kernel 재시작 |
| CLI 로그인 오류 | `codex login status` | `codex login` 후 재실행 |
| 사용량·응답 대기 오류 | 실제 오류코드 | 계정·네트워크 확인, 필요 시 예제 경로 직접 선택 |
| 첫 Test 실패 | 수정 전인지 확인 | 초안은 예상 실패, 5차시에서 수정 |
| 재실행 시 이미 고친 파일 | 이번 폴더 확인 | Run All은 새 폴더 생성, 기존 파일 보존 |
| UI 결과가 다름 | `--exercise-dir` | Notebook이 출력한 동일 경로 사용 |
| 포트 사용 중 | 실행 중 서버 | 포트 변경 후 HTTP 주소도 변경 |

실습 결과 공개나 발표는 필수가 아니다. 4주차 GitHub 연결과 5주차 미니 프로젝트 준비는 별도 운영안을 따른다. Notebook 자체의 `external_write=false`는 GitHub 댓글·push·자동 Merge를 실행하지 않았다는 뜻이다.
