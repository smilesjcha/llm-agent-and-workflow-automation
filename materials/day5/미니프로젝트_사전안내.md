# 5주차 미니 프로젝트 사전 안내

다음 주 마지막 3시간에는 **내가 다시 사용할 수 있는 작은 업무 도구 한 개**를 만듭니다. 4주차 코드를 출발점으로 삼아 입력이나 기능을 바꾸고, 실제 결과 파일과 오류 처리까지 확인합니다. 개인별 발표는 없으며, 질문이나 결과 공유는 원하는 분만 진행합니다.

**운영 시간: 15:00–17:30 개인 제작 150분 / 17:30–18:00 쉬는 시간 및 Q&A 30분**

새로운 서비스를 크게 시작하기보다, 이미 실행한 기능 하나를 자신의 업무에 맞게 개선하는 것을 권장합니다. 모든 Office 파일 형식과 GitHub 배포를 한 번에 구현할 필요는 없습니다.

## 이번 프로젝트의 범위

| 항목 | 최소 범위 | 예시 |
|---|---|---|
| 사용자 | 사용할 사람 한 명 | 일정 담당자, 강사, 구직자, 개발자 |
| 입력 | 주 입력 한 종류 | 업무 목록, 익명 답안, 경력 사실, PR 변경 코드 |
| 결과 | 실제 결과 한 종류 | XLSX, DOCX, PPTX 또는 HTML 작업대 |
| 개선 | 작동을 확인한 변경 한 가지 | 날짜 입력 검사, 새 요약 표, 과장 문장 표시 |
| 검사 | 정상 1건과 실패 2건 | 올바른 입력, 잘못된 입력, 기존 파일 보호 |
| 안내 | 실행 방법과 제한 사항 | 설치 명령, 입력 위치, 결과 경로, 복구 방법 |

아이디어를 적거나 AI에게 질문만 한 상태는 **Ideation**입니다. 파일을 읽고, 코드나 수식을 수정하고, 실행 결과를 확인하는 작업이 **개발 실습**입니다. 코드가 제안된 상태와 실제로 실행한 상태도 구분해서 기록합니다.

추천 개선은 **다음 주 구현할 기능**입니다. 공휴일 계산이나 문항별 가중 배점이 현재 템플릿에 이미 구현된 것으로 이해하지 않습니다. 완성 파일의 모양만 바꾸려면 어떤 사용상의 불편이 줄었는지 함께 확인합니다.

실제 학생 성적, 고객 자료, 회사 비공개 PR, 개인 연락처는 가져오지 않습니다. 수업에 제공한 합성 데이터나 직접 만든 익명 예시를 사용합니다. Word 자료도 사용자 제공 경력으로 구성한 수업 예시이며, 실제 원본 이력서가 아닙니다.

| 파일 뷰어 | 결과 형식을 열 수 있는 앱 준비 | Excel·Word·PowerPoint 또는 LibreOffice |
| AI 도구 | 사용할 계정과 작업 방식 확인 | 첨부형 대화 또는 프로젝트 폴더에서 실행 |
| 원본 보존 | 개인 결과용 새 폴더와 파일명 준비 | 이미 만든 파일을 덮어쓰지 않음 |

설치 명령은 **저장소 루트**에서 실행합니다. 폴더를 바꾸어 실행하면 상대 경로가 달라집니다. Notebook에서 `%pip`를 사용하면 현재 커널에 설치하며, 터미널의 Python과 Notebook 커널이 같은 환경인지 확인합니다.

계정이 준비되지 않거나 사용량 제한에 걸려도 제공 Python·Node 코드의 실행은 이어갈 수 있습니다. 실제 AI와의 추가 대화는 계정과 네트워크 조건에 따라 다릅니다. 설치 복구에 오래 걸리면 다른 형식으로 갈아타기보다 해당 차시의 준비된 기본 코드로 복귀합니다.

## ChatGPT와 Claude의 작업 방식

| 사용 방식 | 수업에서의 입력 | 진행 방법 | 확인할 차이 |
|---|---|---|---|
| ChatGPT 파일 첨부 대화 | 익명 입력 파일과 원하는 결과 설명 | 수정안 또는 생성 파일을 검토하고 다운로드 | 첨부했다고 자신의 로컬 저장소가 자동으로 수정되는 것은 아님 |
| Codex 로컬 작업 | 실습 프로젝트 폴더와 정확한 파일 경로 | 코드 수정, 명령 실행, 테스트와 diff 검토 | 선택한 작업 폴더와 파일·명령 권한 확인 |
| Claude 파일 첨부 대화 | 익명 파일, 화면 캡처, 검토 기준 | 수정안이나 파일 결과를 받아 직접 확인 | 파일 처리 기능과 지원 형식은 계정 설정 확인 |
| Claude Code 로컬 작업 | Local 환경과 실습 프로젝트 폴더 | 파일과 테스트를 읽고 필요한 변경 실행 | Chat 대화와 Code의 실행 환경을 구분 |

이 표는 이번 수업에서 사용할 작업 경로를 구분한 것입니다. 연결 도구나 다른 실행 모드를 추가하면 범위가 달라질 수 있습니다. 파일 첨부형 대화에서는 결과를 다운로드해 직접 실행하고, 로컬 코드 작업에서는 변경 diff와 실행 로그를 확인합니다. [OpenAI 파일 작업 안내](https://learn.chatgpt.com/docs/artifacts-viewer), [Codex CLI 안내](https://learn.chatgpt.com/docs/codex/cli), [Claude 파일 업로드](https://support.claude.com/en/articles/8241126-upload-files-to-claude), [Claude Code Desktop 안내](https://code.claude.com/docs/en/desktop).

모델에게 작업 폴더 전체 권한을 무조건 주거나, 승인 절차를 해제할 필요는 없습니다. 외부 게시·메일 발송·배포는 미니 프로젝트 필수 범위가 아니며, 진행하려면 대상과 내용을 사람이 먼저 확인합니다.

## 주제별 AI 요청 예시

아래 문장은 실제 대화 기록이 아니라 학생이 입력할 요청 예시입니다. 파일 첨부형 대화라면 언급한 파일을 첨부하고, 로컬 코드 작업이라면 실습 폴더를 선택합니다. AI의 “완료했다”는 설명 대신 실제 파일과 실행 결과를 확인합니다.

### PR 리뷰 작업대

1. “`labs/day4/pr_review_lab/review_policy.md`와 `service.py`를 읽고, PR 정보 확인부터 리뷰 미리보기까지의 흐름을 설명해줘. GitHub에 게시하지 말고 중요도별로 의견을 골라 볼 기능의 수정 계획을 제안해줘.”
2. “기존 전체 보기 결과를 유지하면서 P1/P2 필터를 추가해줘. 내 실습 복사본을 사용하고, 표시되는 리뷰 수가 실제 필터 결과와 일치하도록 구현해줘.”
3. “다른 PR 번호와 오래된 commit SHA가 들어온 경우가 여전히 차단되는지 테스트해줘. 기능 테스트를 통과시키려고 기존 승인 검사를 제거하지 마.”
4. “HTML을 직접 열어 전체 보기와 필터 보기를 비교하고, 실행 명령과 한계를 README에 적어줘. 실제 GitHub 게시를 하지 않았다는 점도 구분해줘.”

### WBS 도우미

1. “`student_excel.py`의 `calculate_wbs()`와 `wbs_tasks.json`을 읽어줘. 지금은 토요일과 일요일만 제외하는데, 내가 제공한 공휴일 목록을 추가로 반영하고 싶어. Excel 수식과 Python 계산이 함께 바뀌어야 할 부분을 설명해줘.”
2. “공휴일 인수를 선택값으로 추가해줘. 목록을 주지 않으면 기존 결과를 유지하고, 제공한 날짜만 사용해줘. Excel의 NETWORKDAYS 세 번째 인수에 연결할 범위도 만들어줘.”
3. “공휴일 없음과 평일 공휴일을 검사해줘. 잘못된 날짜와 존재하지 않는 선행 업무도 확인하고, 주말과 공휴일이 겹쳤을 때 두 번 빼지 않는지 테스트해줘.”
4. “새 XLSX를 저장한 뒤 앱에서 재계산한 업무일수와 Python 결과를 비교해줘. 입력 위치와 적용하지 않은 휴일 정책을 README에 적어줘.”

### 시험 채점 도구

1. “`grade_exam()`과 `exam_sample.json`을 읽어줘. 문항별 배점을 추가하려고 해. 현재 결시와 입력 오류를 평균에서 제외하는 규칙을 유지하는 설계를 먼저 설명해줘.”
2. “정답 수와 가중 점수를 다른 이름으로 구분해줘. 배점을 주지 않으면 현재처럼 각 문항 1점으로 처리하고, Excel과 Python의 점수 계산도 같은 기준으로 바꿔줘.”
3. “1~4가 아닌 답안과 정답표 문항 수 불일치를 확인해줘. 배점 목록 길이가 다를 때도 계산을 보류하고, 채점 오류를 0점으로 바꾸지 마.”
4. “합성 학생 한 명의 점수를 손으로 계산한 값과 비교해줘. XLSX에서 조건부서식으로 오류를 찾을 수 있는지 확인하고, 학생 실명이나 실제 성적은 넣지 마.”
