## 완료 기준

“누가 어떤 파일을 입력하면 어떤 결과를 얻는가”를 한 문장으로 적습니다. 파일 형식과 정상 동작을 확인할 기준을 포함합니다.

## Before와 Change

| 구분 | 내 기록 |
|---|---|
| 기존 동작 | 원래 코드에서 재현한 결과 |
| 불편 또는 오류 | 어떤 입력에서 무엇이 문제였는지 |
| 바꾼 파일과 함수 | 정확한 파일명, 함수명 또는 Excel 수식 위치 |
| 변경 내용 | 추가·삭제·수정한 로직 |
| 유지한 규칙 | 기존 정상 동작, 개인정보, 승인 또는 원본 보존 규칙 |
| AI 제안과 내 판단 | 채택한 제안과 채택하지 않은 제안의 이유 |

기획만 한 항목과 실제 구현한 항목을 구분합니다. 기존 파일을 실행만 했다면 기능을 구현했다고 적지 않습니다.

실패 검사는 “프로그램이 깨짐”만 기록하지 않습니다. 잘못된 입력을 어떤 메시지로 거절했고, 원본 파일과 기존 정상 동작을 보존했는지 적습니다. 실패를 고친 경우 재실행 결과도 남깁니다.

## 실행 명령

실제로 성공한 명령을 붙입니다. 명령을 실행할 폴더, 설치 방법, 입력 파일 위치와 출력 경로를 함께 적습니다. 토큰이나 개인 경로 속 민감한 정보는 지웁니다.

```text
작업 폴더:
설치 명령:
실행 명령:
테스트 명령:
결과 경로:
```

## 결과 화면과 내용

| 확인 | 내 기록 |
|---|---|
| 결과 파일 열기 | 사용한 앱과 파일명 |
| 입력과 결과 일치 | 확인한 숫자, 문장 또는 코드 결과 |
| 편집 가능 여부 | Excel 수식, Word 문단, PPT 표 등 |
| 화면 검수 | 잘림, 글꼴, 표 너비, 오류 표시 |
| 수정 전후 화면 | 개인정보를 제외한 이미지 경로 |
| 재실행 | 새 출력 폴더에서 성공 여부 |

## After와 남은 제한

| 항목 | 내 기록 |
|---|---|
| 확인한 개선 | 실제로 달라진 동작과 근거 |
| 측정 여부 | 측정했다면 방법·횟수·전후 값, 미측정이면 미측정 |
| 아직 하지 못한 일 | 구현 예정 또는 미검증 사항 |
| 사용할 수 없는 상황 | 입력 크기, 계정, 네트워크, 폰트, OS 등 |
| 사람 검토가 필요한 부분 | 이력서 사실, 채점 기준, 일정 판단, 리뷰 게시 등 |
| 다음 개선 한 가지 | 다음에 바꿀 가장 작은 기능 |

Git을 사용하는 경우 전체 폴더를 한꺼번에 올리지 않습니다. 변경 내용을 확인하고 필요한 코드·합성 데이터·문서만 선택해 commit합니다. 원격 push나 PR 생성은 자신의 연습 저장소에서 범위를 확인한 뒤 진행합니다.
