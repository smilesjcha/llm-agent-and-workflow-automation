# 업무자동화 프로젝트 선택 가이드

## 핵심 선택

**현재 수업의 다섯 가지 예시에 한정하지 않습니다.** 아래 36개 제안에서 고르거나, 자신의 반복 업무를 직접 제안할 수 있습니다. 중요한 기준은 주제의 크기가 아니라 **입력 파일 한 종류로 실제 결과 한 종류를 다시 생성할 수 있는가**입니다.

이 문서는 강사가 설계한 프로젝트 추천 카탈로그입니다. **36개 서비스가 모두 구현되어 있거나 실제 기업에서 운영된다는 뜻은 아닙니다.** 각 항목의 준비 상태와 새로 만들 부분을 확인하세요. 150분 안에 가능한 범위는 제공 예제를 정상 실행한 환경과 익명 샘플이 준비되었다는 가정이며, 완성 시간을 보장하지 않습니다.

| 선택 기준 | 권장 출발점 |
|---|---|
| 설치·개발이 아직 낯설 때 | 기본 코드가 준비된 PM01·PM02·HR01·ED01·DV01 |
| 파일 처리와 함수 수정을 경험했을 때 | 기본 코드를 응용하는 MK01·HR03 또는 KN01 |
| 자신만의 주제가 분명할 때 | 나머지 제안에서 새 로직 하나만 구현 |
| 목록에 없는 업무일 때 | 사용자·반복 작업·입력·결과·실패 두 건을 정의해 제안 |

기본 시간은 **15:00–17:30 개인 제작 150분**, **17:30–18:00 휴식·Q&A 30분**입니다. 발표 의무는 없습니다. 36개를 모두 설명하거나 만들지 않고 자신에게 맞는 하나만 고릅니다. [진행 시간표와 설치](미니프로젝트_사전안내.md), [개선 기록](개선기록_템플릿.md)을 함께 사용하세요.

## 공통 작업 원칙

- **Ideation:** 주제 선택, 자료 조사, 작업 흐름과 완료 기준 정리. 코드 실행과 구분합니다.
- **개발 실습:** 입력 파일 준비, 함수·수식 구현, 실행, 오류 재현, 결과 파일 열기, 수정 후 재실행.
- **무료 출발 경로:** Python·Node와 로컬 파일을 기본으로 설계합니다. 외부 API 호출은 최소 기능에 필요하지 않습니다. AI와의 개발 대화는 본인 계정 조건을 따르며, 무료 이용을 보장하지 않습니다.
- **결과 형식:** CSV·MD·HTML은 직접 열어 확인합니다. XLSX·DOCX·PPTX는 보유한 문서 앱 또는 무료 LibreOffice로 확인합니다. 설치·호환성은 [4주차 가이드](../day4/2026_Day4_수강생_실습가이드.md)를 따릅니다.
- **AI의 역할:** 정해진 합계·날짜·형식 검사는 코드로 처리합니다. 문장 개선·분류 제안·근거 찾기는 선택적으로 AI를 사용하되, 사람이 정답과 정책을 확인합니다. AI 없이도 규칙·템플릿과 수동 확인으로 첫 결과를 만들 수 있습니다.
- **데이터:** 모든 사례는 합성·익명 파일을 전제로 합니다. 실제 성적, 고객 문의, 이력서 연락처, 비공개 PR을 올리지 않습니다. 아래 파일명은 별도 링크가 없는 한 **학생이 새로 만들 예시 파일명**입니다.
- **안전:** 작업 폴더 밖 파일 접근과 기존 출력 덮어쓰기를 차단합니다. 원격 API를 붙일 때에는 읽기 대상·권한부터 제한합니다. 메일 발송, 게시, Drive 업로드, 고객 상태 변경은 내용과 대상을 사람이 승인하는 별도 단계입니다.

### PM01 · 일정·지연 점검

- **사용자·반복 업무:** PM이 매주 종료일과 진척률을 비교해 지연 업무를 찾는 작업.
- **입력·결과:** 제공 [업무 14개](../../labs/day4/office_lab/sheets/wbs_tasks.json)와 기준일 → 새 `WBS_Mine.xlsx`.
- **150분 최소 기능·추가 범위:** 기존 계산 실행, W04 진척률 수정, 지연 목록 필터 하나 추가. 공휴일·담당자별 부하·알림은 이후 범위.
- **검사:** 정상은 2026-09-25 기준 W04·W05 지연. 실패는 종료일 역전, 존재하지 않는 선행 ID를 각각 거절.
- **사람 확인·API:** 실제 지연 사유와 일정 변경을 PM이 확인. 기본 API 없음. 일정 도구 읽기·업데이트는 별도 설계·승인.
- **재사용:** S 기본 준비. `calculate_wbs()`와 `write_wbs_copy()` 재사용. 지연 전용 CSV 저장기는 새 구현.

### PM02 · 주간 보고서

- **사용자·반복 업무:** 프로젝트 담당자가 WBS 수치를 보고 장표에 다시 옮기는 작업.
- **입력·결과:** 수정한 WBS 14개 → `brief.json` → 편집 가능한 `Project_Brief_Mine.pptx`.
- **150분 최소 기능·추가 범위:** `write_brief(..., tasks=tasks_my)` 연결, 입력 한 건 변경 후 수치·표 확인. 임의 업무 수·여러 프로젝트 비교는 이후 범위.
- **검사:** 정상은 W04 완료 처리 후 완료 5개·지연 1개. 실패는 업무 13개 입력, 이미 존재하는 출력 경로를 거절.
- **사람 확인·API:** 진행률의 근거와 보고 대상이 확인할 메시지 검토. 기본 API 없음. Drive 업로드는 별도 승인.
- **재사용:** S+P 기본 준비. 14개 업무·7장 템플릿만 지원. 다른 경영 지표 보고서는 새 데이터 변환 필요.

### PM03 · 변경 요청 대장

- **사용자·반복 업무:** 운영 PM이 여러 요청을 옮기며 중복 요청과 미결정을 확인하는 작업.
- **입력·결과:** `requests.csv`의 요청 ID·제목·접수일·상태 → 중복 표시가 있는 `change_register.csv`.
- **150분 최소 기능·추가 범위:** 합성 요청 10개, ID 중복 탐지, 상태별 목록. 요청 우선순위 추론·이슈 시스템 연결은 이후 범위.
- **검사:** 정상은 10개 행과 상태별 합계 일치. 실패는 빈 ID, 허용하지 않은 상태 값을 오류 목록에 표시.
- **사람 확인·API:** 요청을 수용할지와 우선순위는 PM 판단. 기본 API 없음. 이슈 등록·수정은 별도 승인.
- **재사용:** 새 구현. S의 입력 검사·새 복사본 정책만 참고하며 요청 처리 함수와 CSV 구조는 새로 작성.

### PM04 · 위험 점검표

- **사용자·반복 업무:** PM이 위험 목록에서 점검 기한과 대응 담당 누락을 찾는 작업.
- **입력·결과:** `risks.csv`의 ID·설명·Role·점검일·상태 → 기한·누락 표시 HTML.
- **150분 최소 기능·추가 범위:** 위험 8건의 기한 초과와 Role 누락 표시. 위험 확률 예측·손실 금액 추정은 제외.
- **검사:** 정상은 기준일 이전 미해결 항목만 표시. 실패는 날짜 형식 오류, 중복 ID를 각각 식별.
- **사람 확인·API:** 실제 위험의 중요도와 대응 수용 여부 검토. 기본 API 없음. 원격 티켓 등록은 별도 승인.
- **재사용:** 새 구현. S의 날짜 검사 방식을 참고하고 HTML에는 사용자 입력을 escape 처리.

### CS01 · 문의 분류

- **사용자·반복 업무:** 고객지원 담당자가 문의를 배송·교환·계정 유형으로 나누는 작업.
- **입력·결과:** 합성 `inquiries.csv` 12건과 `category_rules.json` → `classified.csv`.
- **150분 최소 기능·추가 범위:** 키워드 규칙 3종과 분류 불가 상태, 근거 키워드 표시. LLM 분류와 정확도 비교는 이후 범위.
- **검사:** 정상은 미리 정한 6건의 기대 유형 일치. 실패는 빈 본문, 두 유형이 동시에 맞는 문의를 검토 대상으로 분리.
- **사람 확인·API:** 담당자 배정과 답변은 사람 확인. 기본 API 없음. 고객지원 시스템 티켓 변경은 별도 승인.

### CS02 · FAQ 답변 초안

- **사용자·반복 업무:** 상담 담당자가 같은 질문에 맞는 정책 문구를 찾아 복사하는 작업.
- **입력·결과:** `questions.csv`와 허용한 FAQ 5건의 `faq.md` → 출처 ID를 붙인 `reply_drafts.md`.
- **150분 최소 기능·추가 범위:** 규칙으로 FAQ 선택 후 확인된 문구의 템플릿 조합. 자유 생성·임베딩 검색은 이후 범위.
- **검사:** 정상은 환불 질문에 해당 FAQ ID 연결. 실패는 근거 없음, 서로 충돌하는 FAQ를 답변 보류로 표시.
- **사람 확인·API:** 환불 조건·현재 정책·고객에게 보낼 표현 확인. 기본 API 없음. 메일·상담 게시 기능은 제외.
- **재사용:** 새 구현. M의 근거 확인 흐름 참고만 가능하며 FAQ 로더와 연결 로직은 제공되지 않음.

### CS03 · 상담 인계

- **사용자·반복 업무:** 교대 상담 담당자가 진행 상황과 확인할 일을 다음 담당자에게 전달하는 작업.
- **입력·결과:** 합성 `handoff.json`의 문의·진행 상태·다음 확인 → `handoff.docx`.
- **150분 최소 기능·추가 범위:** 정해진 필드 6개를 Word 제목·표로 구성, 누락 경고. 상담 음성 STT·실시간 CRM 연결은 이후 범위.
- **검사:** 정상은 사건 ID와 다음 할 일 보존. 실패는 필수 사건 ID 누락, 허용하지 않은 상태를 거절.
- **사람 확인·API:** 고객 약속·조치 이력의 사실성 검토. 기본 API 없음. 인계 문서 공유는 대상 확인 후 별도 승인.

### CS04 · VOC 집계

- **입력·결과:** 합성 `voc.csv`의 사건 ID·유형·날짜 → 유형별 건수·비율 Excel.
- **150분 최소 기능·추가 범위:** 3개 유형과 미분류 집계, 전체 건수 대조. 감정 추론·고객별 점수화는 제외.
- **검사:** 정상은 유형 합계가 중복 제거 후 총건수와 일치. 실패는 중복 사건 ID, 잘못된 날짜를 분리.
- **사람 확인·API:** 유형 정의와 중복 사건 처리 기준 확인. 기본 API 없음. 회사 문의 데이터를 자동 수집하지 않음.
- **재사용:** 새 구현. S의 수치 검증·Excel 생성 구조만 참고. VOC 집계 함수는 새로 작성.

- **검사:** 정상은 안건 두 개와 출처 파일 연결. 실패는 없는 자료 ID, 상충하는 상태를 미확인으로 표시.
- **사람 확인·API:** 자료의 최신 버전·회의 목적·공유 범위 확인. 기본 API 없음. 원격 수집·문서 저장 모두 별도 설계.
- **재사용:** 새 구현. M의 근거·사람 확인 흐름 참고. 브리프 구성기·자료 연결기·충돌 검사는 새로 작성.

## 직접 제안하는 프로젝트

목록에 없는 주제도 다음 형식이면 논의할 수 있습니다. 미니 프로젝트 시작 전에 10분 안에 합성 입력을 만들 수 없는 경우, 먼저 입력을 단순화합니다.

| 항목 | 한 문장으로 정할 내용 |
|---|---|
| 사용자 | 어떤 사람이 이 도구를 다시 사용하는가 |
| 반복 업무 | 지금 어떤 파일의 어떤 값을 옮기거나 확인하는가 |
| 입력 | 파일 형식 하나와 필수 열·항목 |
| 결과 | 실제로 열 수 있는 파일 하나 |
| 처리 | 함수·수식으로 고정할 규칙과 AI가 제안할 부분 |
| 완료 | 정상 입력에서 관찰할 값·문장·화면 |
| 실패 | 잘못된 입력 두 종류와 복구 방법 |
| 사람 확인 | 사실·정책·게시에서 사람이 결정할 부분 |

예를 들어 “고객지원 Agent 전체”보다 “합성 문의 12건을 세 유형으로 분류하고 애매한 항목을 따로 보여주는 CSV”가 이번 시간의 범위에 맞습니다. 목록은 선택의 힌트이며 정답 목록이 아닙니다.

## 대화에서 구현까지

아래는 **입력할 요청 예시**이며 실제 실행된 대화 기록이 아닙니다. 파일 첨부형 대화에는 안전한 입력과 관련 코드만 첨부합니다. Codex·Claude Code 로컬 작업에서는 지정한 실습 폴더와 실제 경로를 사용합니다. 제품별 파일 접근·도구 권한은 [기존 안내](미니프로젝트_사전안내.md#chatgpt와-claude의-작업-방식)를 따릅니다.

1. **범위:** “PM01을 응용할게. 매주 WBS에서 지연 업무만 찾는 목록이 필요해. `student_excel.py`와 `wbs_tasks.json`을 읽고 기존 계산을 재사용할 수정 계획, 정상 한 건, 실패 두 건을 먼저 설명해줘. 원격 연결은 제외해줘.”
2. **구현:** “계산 결과에서 지연만 선택하는 함수와 새 CSV 저장기를 구현해줘. 입력과 출력은 작업 폴더 안으로 제한하고 기존 출력 덮어쓰기는 막아줘. 수정한 파일과 실행 명령을 보여줘.”
3. **검증:** “정상 입력에서 W04·W05가 선택되는지, 종료일 역전과 없는 선행 ID가 거절되는지 실제로 실행해줘. 실행하지 못한 검사는 미실행으로 표시하고 원인을 적어줘.”
4. **전달:** “내가 CSV 내용을 확인했어. 새 출력 폴더에서 다시 실행하고 README에 설치·입력·실행·결과 경로·한계를 적어줘. 지연 사유 추론이나 메일 발송까지 구현했다고 표현하지 마.”

2번의 저장기와 테스트는 **이 프로젝트에서 새로 구현할 부분**입니다. 화면에 CSV가 생겼는지, 예상 값이 맞는지, 잘못된 입력을 안전하게 거절했는지까지 확인해야 개발 실습이 됩니다. 시간이 남으면 한 가지 개선만 더하고 [개선 기록](개선기록_템플릿.md)에 Before·Change·Evidence·After·Limit를 남깁니다.
