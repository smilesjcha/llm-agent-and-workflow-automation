# 4주차 PR 리뷰와 문서 자동화

이번 개편은 오전에 GitHub PR 리뷰를 연결하고, 오후에는 같은 작업 방식을 Excel·Word·PPT에 적용한다. 생성된 JSON을 읽는 데서 끝내지 않고 파일을 수정하고, 계산·테스트·렌더 결과를 직접 확인하는 수업이다.

## 편성 판단

전체 원안에는 GitHub 연동 6시간과 회의록·문서 자동화 8시간이라는 모듈이 있었다. 이번 요청에 따라 4주차는 GitHub 핵심 3개 차시와 문서 자동화·통합 5개 차시로 재편했다. 원안의 모듈 시간을 이번 하루에 그대로 이수했다고 주장하지 않는다. API 대량 수집, 실제 원격 게시, 조직 권한 설계는 선택 보충 자료와 5주차 운영 주제에서 다룬다.

3주차에서 이미 다룬 Prompt·코드 리뷰 기준·LangGraph 기본 정의를 다시 긴 이론으로 설명하지 않는다. 4주차에서는 검토 대상 버전, 승인 후 게시, 수식 재계산, 문서 사실 보존, 출력물 검증이라는 새로운 문제를 소유한다.

## 차시별 진행과 발화

### 1차시 대상 PR과 변경 수집

먼저 리뷰 HTML, Gantt Excel, 개선된 경력 문서와 보고용 PPT를 빠르게 보여준다. “오늘은 파일이 만들어졌다는 사실보다, 내가 내용을 바꿨을 때 결과가 맞게 바뀌는지 보겠습니다.” 정도로 하루의 과제를 제시한다.

Repo는 프로젝트 저장소, Branch는 변경을 모으는 작업선, Commit은 저장 시점, PR은 변경을 검토해 달라는 요청이라고 설명한다. SHA는 내용 버전을 구분하는 식별자이며 비밀번호가 아니다. 지난주와 달리 검토 대상이 고정돼 있어야 한다는 점을 주문 서비스 변경 예제로 설명한다.

학생은 Notebook의 PR 예제를 읽고 저장소·PR 번호·SHA를 확인한다. 의도적으로 다른 저장소 이름을 넣어 차단을 확인하고, 올바른 값으로 복구한다. 개인 계정 연결을 완료한 학생만 공개 PR 읽기를 선택한다. 인증이 안 되는 학생은 동일 구조의 fixture로 계속한다.

빠르면 페이지네이션과 변경 파일 누락을 다룬다. 늦으면 원격 읽기를 생략하고 fixture의 target 변경과 검증 함수를 반드시 실행한다.

### 2차시 리뷰 초안과 게시 승인

일반 댓글과 라인 리뷰의 차이는 파일·줄·commit의 연결 여부다. 코드 리뷰의 문장 품질을 다시 설명하지 않고, 좋은 의견이 엉뚱한 줄에 달릴 때의 문제를 보여준다.

학생은 초안 본문을 수정하고 Markdown 및 HTML로 확인한다. 승인 전에는 게시 계획을 만들 수 없고, 승인 후 본문이나 SHA가 달라지면 다시 승인이 필요하다는 조건을 실행한다. 코드에서 승인 값을 True로 놓는 것과 현재 내용에 대한 유효한 사람 확인은 별개다.

실제 GitHub 게시를 기본 Run All에 넣지 않는다. 로컬 미리보기 함수가 저장한 payload와 실제 원격 게시를 구분해 말한다. 제공 코드에는 원격 게시 기능이 없다. 이를 추가로 구현·시연할 때에는 repository·PR·본문을 확인하고 사람 승인 이후에만 전송하도록 설계한다.

실제 Codex CLI 실행 사례는 `Codex_실행사례_및_검증.md`에 있다. 모델은 두 결함을 찾았지만 문제 줄을 5행으로 잘못 표시했다. 원문을 보존한 채 실제 계산식이 6행임을 학생과 확인한다. 이 사례가 '모델 응답 → 코드 근거 → 별도 테스트' 흐름을 설명하는 짧은 시연이다.

빠르면 429·timeout 후 재시도와 중복 댓글을 토론한다. 늦으면 오래된 SHA 차단 한 가지와 승인 후 내용 변경 무효화를 꼭 확인한다.

### 3차시 테스트와 GitHub Actions

AI 리뷰는 결함 후보를 찾고, 테스트는 정해진 입력과 기대값을 비교한다. 두 결과가 사람의 검토를 지원한다. “AI가 좋다고 했습니다”라는 PR 설명 대신 테스트 명령과 실제 결과를 붙인다.

학생은 제공된 결제 계산 코드를 고치고 같은 테스트를 다시 실행한다. 성공하면 자신의 저장소에 workflow 파일을 복사하는 과정을 진행한다. 공유 강의 저장소의 자동화를 켜지 않는다. 기본 권한은 읽기이며 테스트 실행에 API key가 필요하지 않다.

pull_request와 pull_request_target을 단순한 이름 차이로 설명하지 않는다. 신뢰하지 않는 PR 코드를 실행하는 작업에 높은 권한과 Secret을 함께 주면 위험하다는 경계를 설명한다. 실제 CI가 안 되는 경우 로컬 명령과 YAML 파일까지 완성하고 원격 확인은 선택 과제로 남긴다.

### 4차시 Excel WBS와 Gantt

WBS는 일을 완료 가능한 단위로 나눈 목록, Gantt는 기간을 달력 위에 놓은 표현이다. 일정 산출을 LLM에게 맡기기 전에 업무 범위·담당·시작·종료·선행작업을 정의한다. 제공 일정은 수업용 가정이며 실제 조직 일정이 아니다.

Excel의 입력 셀과 수식 셀, 날짜의 내부 값과 표시 형식을 구분한다. 고정 기준일, 업무일 수, 진척도, 종료일과 기준일 비교를 설명한다. Gantt는 색을 직접 칠한 그림이 아니라 날짜 조건에 반응하는 서식이다.

학생은 template의 한 업무를 수정하고 시작·종료일을 바꾼 파일을 새 이름으로 저장한다. Python 검증 함수로 종료일이 시작일보다 빠른 입력을 거절한다. Excel 또는 LibreOffice에서 열어 재계산 후 막대와 상태의 변화를 확인한다. openpyxl은 수식을 저장하지만 계산 엔진이 아니라는 점을 강조한다.

빠르면 선행작업 지연 전파와 실제 휴일 캘린더를 설계한다. 기본 실습이 자동 일정을 계산한다고 오해하지 않도록 현재 구현의 범위를 짚는다.

### 5차시 시험 채점과 Google Sheets

객관식의 정답 비교는 수식으로 결정한다. LLM은 수식 제안·설명·코드 작성에 사용하고 학생의 점수를 추측하는 데 사용하지 않는다. 실제 성적을 AI 서비스에 올리지 않고 합성 답안으로 진행한다.

첨부 화면에서 보이는 구조를 별도 합성 예제로 재현한다. 화면의 초록색은 정답 여부의 표현이며 점수의 원천이 아니다. 정답행과 답안행 비교, 총점, 동점 순위, 문항별 정답률을 각각 다른 계산으로 설명한다. 결시를 0점 응시자로 섞지 않으며 오류 입력은 검토 필요 상태로 남긴다.

학생은 정답 하나, 응답 하나, 빈 답안 하나를 바꾸고 재계산한다. 같은 데이터를 Python 기준 계산과 비교한다. Google Sheets 확장은 완성 XLSX를 자신의 Drive에서 Google Sheets로 변환한 뒤 조건부서식·수식·드롭다운을 확인하는 실제 파일 작업이다. 원본 제공 성적표를 변환하거나 변경하지 않는다.

Apps Script는 합성 실습 시트만 대상으로 한다. 기존 시트를 삭제하거나 기존 조건부서식을 전부 지우는 일반화 코드를 주지 않는다. 추가 기능은 작은 실습 시트 생성에 한정한다.

### 6차시 Word 경력 문서

문장을 매끈하게 만드는 일과 사실을 바꾸는 일을 분리한다. 사용자 제공 경력은 금융 ML, 의료 DL, 교육 LLM, 이커머스 Agent라는 경험의 연결을 보여주기에 적합하다. 재직 기간·새 성과·정확한 비용 절감률을 만들어 넣지 않는다.

학생은 경력 사실 목록을 읽고 Role·문제·기여·성과 근거로 재구성한다. python-docx로 문서의 제목과 문단 스타일을 살펴본 뒤 내용을 수정하고 새로운 DOCX로 저장한다. 근거에 없는 숫자를 넣었을 때 검증이 실패하는 것을 확인한다.

Codex·Claude에 먼저 사실 보존과 수정 금지를 지정한다. 다음 요청에서는 한 경력 항목만 수정하고 결과를 확인한다. 마지막으로 문서 전체의 스타일과 페이지 나눔을 검토한다. 입력 경력의 수치는 사용자 제공 내용이며 객관적 성과 입증 자료가 별도로 첨부된 것은 아니다.

### 7차시 데이터 기반 PPT 생성

보고서 PPT의 입력은 자유로운 장문보다 목적·청중·주장·근거·표 데이터가 분리된 구조가 유용하다. WBS와 PR 결과를 보고용 7장으로 바꾸는 과정을 보여준다. 보고용 예제 PPT와 8시간 수업 교안 PPT는 다른 산출물이다.

학생은 프로젝트 데이터의 한 항목을 바꾸고 제목·표가 함께 갱신된 PPT를 생성한다. 표를 이미지로 붙이면 편집이 어려워진다는 차이를 보여준다. 초안을 렌더링하고 줄바꿈·한글 폰트·최소 글자 크기를 확인한다.

AI가 만든 20장의 유사한 문장을 읽는 과제가 아니다. 한 장의 목적과 그 근거를 분명히 정하고, 같은 데이터를 여러 군데 복사했을 때 생기는 불일치를 코드로 줄이는 실습이다.

### 8차시 결과 통합과 개인 프로젝트

학생은 자기 실행 폴더에서 결과를 열고 파일별 입력·출력·검증 명령을 README로 정리한다. 파일 생성과 성공한 검증을 분리해 기록한다. 원문·임시 결과·승인된 배포 파일의 폴더를 나누고 외부 공유는 별도 단계로 둔다.

5주차 마지막 세 차시의 프로젝트 후보를 제시한다. WBS 갱신 도우미, 채점 검토 도우미, 경력 문서 개선 도우미, 주간 보고 PPT 생성기, PR 리뷰 정리 도구 중 하나다. 입력 1종과 주요 기능 1개를 기준으로 선택하고 먼저 동작할 수 있는 최소 범위를 적는다.

5주차는 15:00~17:30 제작·검증·개선, 17:30~18:00 쉬는 시간·Q&A다. 발표는 선택이고 개선 전후 화면이나 README만으로도 과정을 정리할 수 있다.

## 참고자료 확인 범위

제공 Drive 링크는 네이티브 Google Sheet가 아닌 Excel 파일임을 메타데이터로 확인했다. 원본 내부 수식과 조건부서식은 로컬 파일로 확인하지 못했으므로 첨부 화면에서 관찰한 구조만 참고했다. 원본의 실명·성적·링크는 강의 PPT·코드·배포 파일에 포함하지 않는다. 수업 예제 수식은 별도 합성 데이터로 검증한다.

제품 기능은 공식 문서를 기준으로 설명한다. 실제 Desktop 계정에서 실행한 화면과 작성한 대화 예시는 구분한다. 계정·OS·조직 정책에 따라 화면과 제공 기능이 다를 수 있으므로 선택 기능은 기본 실습의 전제 조건으로 두지 않는다.
