# 4주차 실습 가이드

## 오늘 만드는 결과

PR 리뷰와 코드 테스트, Excel 일정표·채점표, Word 이력서, PPT 보고서를 직접 만듭니다. Codex·Claude는 작업을 설명하고 코드를 개선하는 데 활용하며, 실제 계산과 파일 생성은 제공한 코드로 실행합니다.

시작 파일은 [day4_pr_document_automation.ipynb](day4_pr_document_automation.ipynb)입니다. [실행 결과가 포함된 Notebook](day4_pr_document_automation.executed.ipynb)은 결과 비교용입니다. 직접 실습할 때는 실행 전 Notebook을 열어 주세요.

Notebook 상단에도 현재 커널의 누락 패키지를 설치하는 코드가 있습니다. 실제 API key나 Google Sheets 수정 권한은 기본 실습에 필요하지 않습니다.

## 실제로 수정하는 구간

### 1~3차시 코드와 리뷰

1. Notebook의 첫 셀부터 실행해 경로와 패키지를 확인합니다.
2. 1차시에서 출력한 `pr/my-exercise/checkout.py`를 VS Code로 엽니다.
3. 처음 테스트는 정상 쿠폰 1개 통과, 초과 쿠폰·잘못된 입력 4개 실패입니다. 의도한 시작 상태입니다.
4. 결제액을 0 이상으로 제한하고 잘못된 가격·수량·쿠폰을 거부하도록 **기능 코드**를 수정합니다.
5. 2차시의 `check_exercise()` 셀을 다시 실행합니다. 테스트 기대값을 바꾸지 않습니다.
6. 별도 `pr/reference-only/` 폴더는 참고 구현 검증용입니다. 내 코드의 결과와 구분합니다.
7. `HUMAN_CONFIRMED=True`는 리뷰 내용을 읽은 사람이 직접 선택할 때만 사용합니다. 그래도 실제 GitHub에 게시하지 않고 payload만 만듭니다.

`APPLY_REFERENCE_FIX=False`가 기본입니다. True로 바꾸면 참고 구현을 적용하므로 수강생의 직접 수정 결과와 구분해야 합니다.

2차시의 `RUN_CODEX_LIVE=False`도 기본값입니다. 본인의 CLI 로그인·모델 접근·계정 사용량을 확인한 다음 True를 선택하면 실제 Codex 리뷰 원문을 생성합니다. 터미널에서는 다음처럼 실행합니다.

```bash
python -m labs.day4.pr_review_lab.codex_review --live --output output/my-review.md
```

실패하면 fixture로 자동 대체하지 않습니다. 리뷰의 파일 줄 번호·재현 입력을 직접 확인하세요. 실제 강사 실행에서도 결함 설명은 맞았지만 줄 번호는 틀린 사례가 있었습니다. 자세한 기록은 [Codex 실행 사례](Codex_실행사례_및_검증.md)에 있습니다.

### 4~5차시 Excel

1. `my_working_days()`에서 금요일~월요일이 2근무일로 계산되는지 확인합니다.
2. `tasks_my`의 진행률과 담당 Role을 바꾸고, 같은 행의 상태가 바뀌는지 확인합니다.
3. 새 Excel을 열어 Gantt 표시와 수식이 유지되는지 확인합니다.
4. 채점에서는 `my_answer_status()`의 정답·오답·미응답·입력 오류를 구분합니다.
5. 합성 보기 오류 9를 1로 수정한 뒤 점수와 통계 포함 인원이 바뀌는지 확인합니다. 실제 답안은 원본 근거 없이 고치면 안 됩니다.
6. 정답표를 바꾼 실험은 별도 메모리 복사본에서 수행하고 `excel/Exam_changed_key.xlsx`로 저장합니다. D8=1인 원본 비교 파일과 D8=2인 새 파일을 각각 열어 점수·등수·정답률을 비교합니다. 원래 정답표를 보존합니다.
7. Excel은 문서 앱에서 재계산하고, CSV는 Python 독립 계산 결과로 비교합니다. `openpyxl`이 Excel 수식을 계산한 것은 아닙니다.

현재 예시 양식은 WBS 14개 작업, 시험 40문항·28행입니다. 더 많은 작업이나 학생을 추가하려면 입력 영역·수식·조건부서식·테스트를 함께 확장합니다. 단순히 행만 붙이는 작업으로 끝내지 않습니다.

### 6~7차시 Word와 PPT

1. `my_rewrites`에서 사실 ID를 고르고, 없는 수치나 직함을 추가하지 않는 문장으로 바꿉니다.
2. Word 수정 전·후를 열어 같은 사실을 더 쉽게 읽을 수 있는지 비교합니다.
3. `REQUIRES_HUMAN_REVIEW`는 정상 반환입니다. 숫자 검사를 통과해도 경력의 사실성과 표현은 사람이 확인해야 합니다.
4. `prepare_brief(..., tasks=tasks_my)`에 4차시에서 바꾼 입력을 전달합니다.
5. Node.js로 실제 PPT를 생성합니다. 미설치 시 안내가 표시되며, 설치 후 해당 셀부터 다시 실행합니다.
6. PowerPoint에서 7장을 모두 열어 수치·제목·글꼴·표의 잘림을 확인합니다. 구조 검사만으로 시각 검사가 끝나지는 않습니다.

## 자주 막히는 부분

| 상황 | 먼저 확인할 것 | 해결 |
|---|---|---|
| `ModuleNotFoundError` | Notebook 커널과 설치한 Python이 같은지 | `.venv` 커널 선택 후 상단 설치 셀 실행 |
| 실습 폴더를 못 찾음 | 저장소 전체를 받았는지 | Notebook만 따로 복사하지 않고 전체 자료 사용 |
| 처음 pytest 실패 | 초과 쿠폰·잘못된 입력 테스트인지 | 정상 시작 상태. checkout.py 직접 수정 |
| `OUTPUT_EXISTS` | 같은 파일을 다시 생성했는지 | 새 이름 사용 또는 첫 셀부터 새 실행 폴더 생성 |
| Excel 값이 비어 보임 | 수식을 계산하는 앱에서 열었는지 | Excel·LibreOffice로 열고 재계산. CSV와 비교 |
| PPT 생성 미실행 | Node.js·PptxGenJS 준비 여부 | 설치 명령 후 7차시 생성 셀 재실행 |
| SHA·중복 오류 | 의도한 실패 시뮬레이션인지 | 예상된 차단은 검증 성공. 실제 PR이면 새 diff로 검토 |
| 한글 글꼴 깨짐 | 문서 앱의 글꼴 설치 여부 | NanumGothic 설치 또는 제공 코드에서 한글 글꼴 변경 |
