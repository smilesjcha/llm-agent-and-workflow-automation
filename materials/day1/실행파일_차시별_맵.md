# 1일차 실행 파일·활동 분류 맵

`실습`은 설치·코드 작성·명령 실행·테스트·배포처럼 수강생이 소프트웨어를 직접 다루는 구간에만 사용한다. 문제를 고르고 기준을 적는 활동은 `Ideation`, 공개 자료를 찾고 조건을 확인하는 활동은 `자료 수집`, 상태·정책을 종이에 구조화하는 활동은 `설계 워크숍`으로 구분한다.

| 차시 | 활동 분류 | 직접 사용할 파일·명령 | 실행 결과 |
|---|---|---|---|
| 1차시 | 강사 라이브 Demo + 개인 Ideation | `python -m src.meeting_demo` | `transcript.json`, `meeting_result.json` |
| 2차시 | 소프트웨어 실습 | `src/day1_agent.py`, `tests/test_day1_agent.py` | 정상 ToolResult, 차단 error code |
| 3차시 | 자료 수집 + Prompt/Schema 소프트웨어 실습 | `data/meeting_sample_ko_12min*`, `src/langchain_lab.py` | evidence가 있는 typed JSON |
| 4차시 | 개발환경 세팅 실습 | `requirements-day1.txt`, `.venv`, VS Code, Git, GitHub, Codex | interpreter 경로, branch, diff, test, 선택 PR |
| 5차시 | Agent 구현·테스트 실습 | `src/day1_agent.py`, `pytest` | 정상·실패·중복 실행 19개 test 중 관련 test 통과 |
| 6차시 | 모델 Adapter 실행 실습 | `src/langchain_lab.py`, `requirements-local-llm-optional.txt` | fixture/Ollama 선택, fallback 결과 |
| 7차시 | LangChain·LangGraph 구현 실습 | `07_langchain_langgraph_workflow.ipynb`, `src/langgraph_lab.py` | interrupt payload, approve/edit/reject state |
| 8차시 | STT·관측·평가 실행 실습 | `src/meeting_demo.py`, `src/observability_lab.py`, `src/workflow_service.py` | quality gate, local trace, READY/HOLD |

## 한 번에 전체 검증

```bash
source .venv/bin/activate
python -m pytest -q
python scripts/build_langchain_langgraph_demo.py
python -m src.workflow_service --decision approve --out output/day1-workflow
python -m src.workflow_service --decision reject --out output/day1-workflow-reject
```

강사와 수강생 모두 이 명령에서 실패하면 raw traceback 전체를 따라가지 않고 첫 오류·현재 Python 경로·작업 폴더를 먼저 확인한다.
