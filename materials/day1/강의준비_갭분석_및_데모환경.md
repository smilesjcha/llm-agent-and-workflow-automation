# 1일차 강의 준비 갭 분석과 데모 환경

## 결론

1일차의 핵심 데모는 로컬 VS Code·Terminal·Notebook·GitHub PR까지면 충분하다. Vercel은 Agent 제어·test·사람 승인보다 앞에 둘 필요가 없으며, 1일차에는 배포하지 않는다. Vercel은 Day 5 최종 결과를 읽기 전용 화면으로 보여주는 선택 확장으로 분리한다.

## 수업 전에 반드시 끝낼 것

완료:

1. 원격 GitHub `main`에 기능 단위 커밋을 순서대로 push했다.
2. GitHub Actions에서 10 tests와 whitespace 검사가 통과했다.
3. `data/demo_meeting.wav`를 fixture fallback까지 포함해 사전 실행했다.
4. 270장 PPT와 270쪽 PDF의 전체 렌더·오버플로·중복 메시지 검사를 마쳤다.
5. 별도 `.venv`에서 Notebook Run All과 10 tests를 통과했다.
6. `faster-whisper`의 `tiny` 모델로 66초·약 17분 WAV를 실제 전사했다. 짧은 파일은 `READY`, 상세 파일은 깨진 문자 탐지로 `HOLD`가 나오는 것을 확인했다.

강의 전 남은 확인:

1. 교육용 PR 한 건을 만들고 diff·CI·리뷰 화면을 캡처한다.
2. Codex GitHub Code Review를 사용할 계정과 repository 연결 여부를 확인한다.
3. 수업에서 `small` 모델을 쓸 경우 전날 미리 내려받아 cold start를 없앤다. 당일 안정성 점검은 이미 검증한 `tiny`로 한다.
4. LangSmith에는 합성 데이터만 보내고 API key·project name을 화면에서 가린다.
5. 발표 모드에서 터미널 글자 크기, 브라우저 알림, 사용자 홈 경로가 보이지 않는지 확인한다.

## 강사 당일 15분 사전 점검

아래 순서까지만 통과하면 1일차 로컬 실습은 진행할 수 있다.

~~~bash
source .venv/bin/activate
python -m pytest -q
mkdir -p tmp/preflight
python -m jupyter nbconvert --to notebook --execute \
  materials/day1/01_agent_foundation.ipynb \
  --output-dir tmp/preflight --output executed.ipynb
python -m src.meeting_demo \
  --audio data/demo_meeting.wav \
  --transcript data/demo_meeting_transcript.txt \
  --out output/day1-demo \
  --model tiny --device cpu --compute-type int8
git status --short
~~~

확인할 출력은 `10 passed`, Notebook 실행 성공, `mode=local_stt`, `quality_gate=READY`, `automatic_email=false`, `requires_human_approval=true`이다. 로컬 STT가 실패해 `mode=fixture`가 나오면 수업은 계속할 수 있지만 품질 Gate는 `HOLD`여야 한다.

## Vercel을 언제 쓰는가

다음 조건을 모두 만족할 때만 Day 5 선택 확장으로 쓴다.

- 로컬 pipeline과 unit test가 먼저 통과한다.
- 화면은 합성 meeting_result.json만 읽는다.
- 고객정보·실제 회의·API key를 브라우저에 보내지 않는다.
- 외부 발행·메일·DB 쓰기 기능이 없다.
- Preview deployment를 사람이 확인한 뒤에만 Production으로 승격한다.

1일차에 Vercel을 넣으면 계정 연결·프레임워크·배포 오류가 Python·Git·Agent의 핵심 목표를 압도할 가능성이 크다. 따라서 1일차 장표에는 “최종 결과를 공유하는 선택 경로”로만 예고한다.

## Codex와 Vercel 데모를 만들 때의 대화 예시

강사:

~~~text
Objective: 합성 meeting_result.json을 읽기 전용으로 보여주는 작은 웹 Demo를 만들어줘.
Scope: web-demo 폴더만 생성.
Data: data/meeting_sample_ko_12min_expected.json의 복사본만 사용.
Do not: API key, 실제 회의, 외부 쓰기, 메일, DB를 추가하지 말 것.
UI: Summary, Decisions, Action Items, Evidence, Human Review 상태.
Verify: build 성공, 빈 데이터·잘못된 JSON 처리 test.
Deliver: 계획, diff, 실행 명령, test와 build 결과.
~~~

Codex가 계획을 제안하면 강사는 다음을 확인한다.

1. web-demo 밖의 파일을 바꾸지 않는가?
2. 합성 JSON만 client에 포함되는가?
3. 잘못된 JSON과 빈 Action Item 예외가 있는가?
4. 배포 전에 local build가 통과하는가?
5. Production 배포는 자동으로 수행하지 않고 Preview URL을 먼저 주는가?

## Vercel 캡처 순서

1. Codex 작업 계약 입력
2. 생성된 web-demo diff
3. local test와 build
4. GitHub Draft PR
5. Vercel Preview deployment
6. Summary·Action Item·Evidence 화면
7. 잘못된 JSON fallback 화면
8. 사람 확인 후 Production 승격 여부 결정

이 흐름은 Day 5 선택 장표로 만들고, Day 1 본편에는 넣지 않는다.
