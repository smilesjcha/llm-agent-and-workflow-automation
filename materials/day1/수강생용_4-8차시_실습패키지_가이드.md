# 수강생용 1일차 4~8차시 실습 패키지 가이드

## 먼저 알아둘 것

12시부터는 자료를 읽는 활동이 아니라 준비된 Python·Notebook 코드를 직접 실행한다. 4차시에서 연 `04_ollama_agent_workflow.ipynb`를 5·6차시까지 계속 사용하고, 7차시에 `07_langchain_langgraph_workflow.ipynb`로 넘어간다.

현재 강사 PC에는 Ollama 0.32.15, local server, `qwen3:4b` 2.5GB model이 준비되어 있다. Qwen Tool Call은 실제 성공했다. 선택 실습으로 GPT-5.6 Luna Responses API도 같은 Tool·LangChain 계약에 연결한다. 로컬 모델·API 키가 없거나 모델 응답이 schema를 지키지 못하면 이유를 남기고 fixture로 복구한다.

## 자료를 받는 두 가지 방법

### GitHub에서 받기

```bash
git clone https://github.com/smilesjcha/llm-agent-and-workflow-automation.git
cd llm-agent-and-workflow-automation
```

이미 받은 사람은 본인이 수정한 파일을 먼저 보관한 뒤 강사가 안내한 시점에만 `git pull`을 실행한다.

### 강사가 별도 ZIP으로 제공하기

강사는 저장소에서 다음 명령으로 비밀정보와 43MB 상세 음성을 제외한 배포 ZIP을 만든다.

```bash
python3 scripts/build_day1_student_bundle.py
```

생성 위치는 `dist/day1-student-lab-bundle.zip`이다. 상세 음성까지 포함해야 할 때만 아래 옵션을 사용한다.

```bash
python3 scripts/build_day1_student_bundle.py --include-long-audio
```

## 최초 1회 환경 준비

터미널에서 설치하는 기본 경로:

```bash
python3.12 --version
python3.12 -m venv .venv312
source .venv312/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install -r requirements-day1.txt
python -m pip install -r requirements-local-llm-optional.txt
python -m pip install -r requirements-openai-optional.txt
python -m pip check
python -m pytest -q
```

Windows PowerShell:

```powershell
py -3.12 --version
py -3.12 -m venv .venv312
.\.venv312\Scripts\Activate.ps1
python -m pip install --upgrade pip setuptools wheel
python -m pip install -r requirements-day1.txt
python -m pip install -r requirements-local-llm-optional.txt
python -m pip install -r requirements-openai-optional.txt
python -m pip check
python -m pytest -q
```

기존 `.venv`가 Python 3.9라면 재사용하지 않는다. 가상환경의 Python 버전은 내부에서 업그레이드할 수 없으므로 새 `.venv312`를 만들고 VS Code Interpreter와 Notebook Kernel도 `.venv312`로 선택한다. `pip3 install -r requirements*.txt`는 OpenAI·STT 선택 패키지까지 한꺼번에 설치하므로 사용하지 않는다.

터미널 설치가 어려우면 Python 3.12 Kernel을 선택한 뒤 `04_ollama_agent_workflow.ipynb` 상단의 `필요한 library 설치` 셀부터 실행한다. 이 셀은 없는 library만 설치하며 선택 provider library가 실패하면 fixture 경로를 안내한다. 설치 직후 import 오류가 계속되면 Notebook의 Kernel을 재시작한다.

## 4~8차시 실행 순서

| 차시 | 직접 열 파일 | 실행할 것 | 완료 화면 |
|---|---|---|---|
| 4차시 | `04_ollama_agent_workflow.ipynb` | 설치 셀→Python 경로→Ollama/OpenAI 진단→좁은 test | provider 상태 JSON·`8 passed` |
| 5차시 | 같은 notebook | fixture 정상→경로 이탈 차단→Qwen/GPT Tool Call→전체 test | `SUCCESS`·`POLICY_BLOCKED`·fallback |
| 6차시 | 같은 notebook | LCEL fixture→Ollama→OpenAI 요청→정책 결과 비교 | typed output·`provider_used`·`fallback_reason` |
| 7차시 | `07_langchain_langgraph_workflow.ipynb` | LCEL→StateGraph→interrupt→approve/edit/reject | 세 terminal state JSON |
| 8차시 | 터미널과 `src/workflow_service.py` | STT/fixture→trace→평가→release gate | `trace.json`·`READY/HOLD` |

최종 기준은 test 개수를 암기하는 것이 아니라 전체 `pytest -q`가 모두 통과하는 것이다.

## Ollama 실제 모델 경로

강의 전 네트워크가 안정적인 곳에서 한 번만 실행한다.

```bash
ollama --version
ollama run qwen3:4b
ollama list
curl http://127.0.0.1:11434/api/tags
```

`qwen3:4b`는 약 2.5GB다. 수업 중 다운로드를 기다리지 않는다. 모델이 없으면 notebook에는 `OLLAMA_MODEL_MISSING` 또는 요청 실패 이유가 남고 `provider_used=fixture`로 계속된다.

## GPT API 선택 경로

채팅·노트북·PPT에 API key를 붙여 넣지 않는다. 이미 노출한 키는 폐기하고 새 키를 발급한 뒤 다음처럼 로컬 파일에만 넣는다.

```bash
cp .env.sample .env
# 편집기로 .env의 OPENAI_API_KEY placeholder만 새 키로 교체
# 실제 API 비교 시에만 RUN_OPENAI_LIVE=1
```

노트북 진단은 `api_key_configured=true/false`만 출력하며 키 값은 보여주지 않는다. `RUN_OPENAI_LIVE=0`이면 `OPENAI_LIVE_OPT_IN_REQUIRED`를 남기고 fixture로 복구하므로 Run All에서 예상치 못한 비용이 발생하지 않는다.

## 막혔을 때 복구 순서

1. Kernel과 terminal의 Python이 같은지 `sys.executable`로 확인한다.
2. 전체를 반복 실행하지 말고 처음 실패한 셀의 마지막 오류 한 줄을 읽는다.
3. library 오류면 상단 설치 셀을 한 번 실행하고 Kernel을 재시작한다.
4. Ollama 오류면 `probe_ollama()`에서 CLI·server·model 중 어디가 준비되지 않았는지 확인한다.
5. OpenAI 오류면 SDK·새 키·`RUN_OPENAI_LIVE` 세 상태만 확인하고 키 자체는 화면에 출력하지 않는다.
6. 10분 안에 해결되지 않으면 fixture로 바꾸고 다음 차시까지 진행한다.
7. `executed.ipynb`에서 기대 출력 형태를 확인하되, 자신의 notebook도 직접 실행한다.
